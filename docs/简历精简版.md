# 遥感变化检测（RS-CD）论文问答系统：RAG + 领域微调

> 项目定位：面向遥感变化检测研究者的**论文检索增强问答系统**，用 RAG 提供可溯源证据，用领域微调（SFT/DPO）改进"忠实抽取 + 引用 + 拒答"行为。
> 状态：`engineering_complete`（链路全通，微调收益待更长训练验证）。诚实边界：自动评测为行为工程评测，不声称可靠推理专家。

## 一、项目做了什么

一句话：基于 Qwen2.5-7B + bge-m3 + FAISS，构建覆盖 120 篇变化检测论文的检索增强问答系统，复刻 SFT/DPO 对齐链路，并用"留出论文隔离 + Oracle 对照"评测把检索误差与生成误差分开算账。

### 系统架构

```
论文语料(arXiv 120篇) ──> 摘要分块 ──> BM25 + bge-m3向量(FAISS) ──> 混合检索 + bge-reranker重排
                                                                        │
问题 ───────────────────────────────────────────────────────────────> 证据 ──> Qwen2.5-7B ──> 带引用答案
                                                                        │
                                                  领域微调(SFT/DPO/LoRA+merge)
```

### 评测先行（核心方法论）

1. **留出论文隔离**：120 篇论文按整篇论文切分，~52 篇留出（不进语料）、~68 篇进语料，避免同论文泄漏。
2. **189 条评测题**：来自留出+训练论文，每题带金证据段落，覆盖名称/数字/拒答。
3. **Oracle 对照**：`Base+正确证据` vs `Base+RAG`，把"检索错误"与"生成错误"分离。

## 二、结果

### 2.1 检索（可靠、强）

| 指标 | 值 |
|---|---|
| 检索召回（训练论文，RAG 模式） | **100%**（118/118 金论文被召回） |
| 留出论文召回 | 0%（符合预期，留出论文不进语料） |

**结论：检索不是瓶颈，误差几乎全在生成端。**

### 2.2 生成（基座 Qwen2.5-7B-Instruct）

| 指标 | Oracle（给对证据） | RAG（检索） |
|---|---:|---:|
| 拒答正确率 | 100% | 100% |
| 名称/数据集覆盖 | 65.1%（41/63） | 71.4%（45/63） |
| 引用率（[n] 标注） | 24.1% | 13.6% |

### 2.3 领域微调（复刻 MedicalGPT 链路）

| 阶段 | 配置 | 结果 |
|---|---|---|
| SFT | 7B BF16 LoRA r=8，50 步，双卡 DDP，1000 条领域数据 | train_loss 2.88 → eval_loss 0.935 |
| DPO | 以 merged SFT 为基座，50 步，单卡，500 偏好对 | train_loss 0.523 |
| merge | LoRA 合回基座 | 可独立部署，独立加载验证通过 |

**诚实结论**：50 步 SFT 未改变名称覆盖（65%→65%），DPO 反而使其退化（65%→46%）。这与偏好数据质量（合成）与训练步数不足有关，是真实的 ablation 发现，而非"调参调出提升"。

## 三、诚实边界（简历必须写清）

1. **RAG 提供证据、模型理解证据，两者都可能出错**（不写"RAG 保证正确"）。
2. 微调提升"忠实/引用/拒答"等**生成行为**，不提升事实正确性（事实来自检索）。
3. 自动评测（字段-数字-单位、引用、拒答）是**行为工程评测**，不替代人工质量评审。
4. 第一轮"数字忠实"指标因评测正则 bug（误提取 `Sek` 伪字段）不可靠，已修复，待重测。

## 四、简历 bullets（可直接用）

- 基于 Qwen2.5-7B、bge-m3、FAISS 与 BM25 混合检索，构建覆盖 120 篇遥感变化检测论文的检索增强问答系统，支持逐条引用溯源；检索召回 100%。
- 设计"留出论文隔离 + Oracle 对照"评测：189 条带金证据的评测题，把检索误差与生成误差分账，发现误差集中在生成端（名称覆盖 65%、引用率 24%），而非检索端。
- 复刻 SFT/DPO 对齐链路（LoRA r=8 + merge，7B 双卡），验证了 50 步偏好对齐在合成数据上提升有限、DPO 反而退化的边界，形成"按任务选训练策略"的工程判断。
