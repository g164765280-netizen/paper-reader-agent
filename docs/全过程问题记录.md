# 遥感专家 Agent —— 全过程问题记录（踩坑 + 架构决策）

> 本文档记录从「接手概念题（PaperQA2）」到「人格层四层能力落地」的**完整问题清单**，
> 供后续接手人快速了解"哪里踩过坑、为什么这么设计"。
> 按时间线分阶段，每个问题标【现象】【根因】【解决】。

---

## 一、项目目标回顾

做一个**遥感变化检测领域专家 Agent**，让用户通过自然对话深入理解这个领域。

四个能力台阶（递进）：
1. **理解层**：读懂论文语境、知道实验结果、清洗概念、带出处回答（RAG）
2. **归纳层**：同语境下，不同论文的解法 + 实验结果横向对比
3. **创见层**：发挥 LLM 基模能力，提新解决思路
4. **协作层**：多 agent 讨论概念

最终架构采用 **DSH「一切皆插件」思想**：能力 = 插件，人格 = 对话角色，统一契约，可插拔后端。

## 二、阶段一：接手概念题（PaperQA2 流程）

### 问题 1：交接文档路径错误
- 【现象】用户说 `docs/概念题交接文档.md`，但工作目录 `/Users/guozi/Desktop/deepseek` 是空的。
- 【根因】项目实际在 `/Users/guozi/Desktop/领域文献阅读Agent/`，不是当前会话工作目录。
- 【解决】通过全盘搜索定位真实项目路径。

### 问题 2：vLLM 启动参数错误
- 【现象】`--tool-call-parser qwen3` 报错 "invalid tool call parser"。
- 【根因】vllm 0.16 的合法 parser 名是 `qwen3_xml`，不是 `qwen3`。
- 【解决】PaperQA2 是纯 chat completion 不需要 tool-calling，直接去掉该参数。

### 问题 3：paperqa `aadd` 传文本报 Errno36
- 【现象】`docs.aadd(text, ...)` 报 "File name too long"。
- 【根因】`aadd(path)` 的 `path` 参数必须是**文件路径**，传文本字符串会被当文件名处理。
- 【解决】先把每篇论文正文写入 `.txt` 文件，再 `aadd(文件路径)`。

### 问题 4：`summary_llm` 默认还是 gpt-4o
- 【现象】改了 `Settings(llm=...)`，aquery 仍报 "Missing credentials"（试图调 gpt-4o）。
- 【根因】paperqa 有三个 LLM 角色：`llm`（主）、`summary_llm`（摘要/答题）、`agent.agent_llm`（agent 流程）。只设 `llm` 不够，后两个默认还是 gpt-4o。
- 【解决】`llm` / `summary_llm` / `agent.agent_llm` 三个都设成本地 Qwen3-8B。

### 问题 5：Qwen3 思考模式污染答案
- 【现象】vLLM 输出里全是 `<think>...</think>` 思考内容。
- 【根因】Qwen3 内建 thinking 默认开启。
- 【解决】通过 `litellm_params` 的 `extra_body: {"chat_template_kwargs": {"enable_thinking": False}}` 关思考。

### 问题 6：contexts 提取字段名错误
- 【现象】提取的 `context.citation`、`context.name` 全是空。
- 【根因】paperqa 2026.8.12 的 `Context` 顶层字段是 `id`(pqac-xxx)/`context`(文本)/`text`(Text对象)/`score`，没有 `citation`/`name`。
- 【解决】正确字段：`ctx.text.doc.citation`（论文ID）、`ctx.text.name`（chunk名）、`ctx.id`（pqac引用id）。

### 问题 7：judge 截断 contexts 导致误判"编造引用"
- 【现象】grounded 指标被误判为 20%（实际应该 90%+）。
- 【根因】judge 脚本只传前 8 条 context，而答案引用的 chunk 可能排在第 9/10 条，被截断后 judge 找不到对应引用，误判"编造"。
- 【解决】按答案里实际引用的 pqac-id/chunk 名**过滤**后再传 judge，而非简单取前 N 条。

## 三、阶段二：分析错题根因（relevance 卡在 74-76%）

### 问题 8：摘要环节写反术语
- 【现象】8B 把"Recall 低=漏检"答成"偏重避免误报"，且英文术语配错（漏检=误报）。
- 【根因】paperqa 的 **summary 环节**用同一个 8B 把检索原文**转述压缩**成摘要，转述时把成对概念（Precision/Recall、漏检/误报）写反。错误层层传递到答题。
- 【验证】语料原文里其实有正确的公式定义（`recall = tp/(tp+fn)`），但 8B 摘要没选中它。
- 【解决方向】关摘要（evidence_skip_summary）直读原文 → relevance 升到 84%（见问题 11）。

### 问题 9：权威词条注入是"双刃剑"
- 【现象】注入 concepts.json 31 条权威词条后，relevance 只净 +2%（74→76%）。
- 【根因】权威词条能"提供定义"，但不能"强制 8B 正确使用定义"。8B 读到 precision/recall 定义，依然把关系答反。
- 【结论】权威词条对 grounded（引用）有用，对 relevance（理解）帮助有限——瓶颈在 8B 理解能力，不在缺知识。

## 四、阶段三：多轮评测 + 置信区间

### 问题 10：API key 余额不足
- 【现象】judge 跑 150 题时中途报 `402 INSUFFICIENT_BALANCE`。
- 【根因】旧 key 欠费。
- 【解决】换新 key（存服务器 `.mentor_env`，chmod 600）。

### 问题 11：关摘要导致 grounded 暴跌
- 【现象】`evidence_skip_summary=True` 后 relevance 74→84%（好），但 grounded 100%→14%（崩）。
- 【根因】摘要环节同时承担**两个功能**：①压缩（省上下文）②打分过滤（滤掉不相关 chunk）。关掉摘要把②也关掉了，无关 chunk 混进引用。
- 【结论】关摘要只救 relevance，毁引用，**不可单独用**。要兼得需"关摘要 + 补一个非 LLM 的 embedding 相似度重排过滤"（未实现，留作待办）。

### 问题 12：数字题准确率报告不一致
- 【现象】旧报告写 93.3%（28/30），实际 eval_set_v9 是 96.7%（29/30）。
- 【根因】eval_set_v9 数据后来被更新过（题20 修复了），报告没同步。
- 【解决】以 eval_set_v9 为准，准确率 96.7%。

## 五、阶段四：插件化 + 人格层

### 问题 13：数字题「论文名→paper_id」缺失
- 【现象】真实对话问"BIT 的 F1"，插件查不到，退回泛答"没有资料"。
- 【根因】评测集题目**自带 paper_id**，但真实对话用户只说方法名/论文名，没有 ID，缺"论文名→ID"的消歧。
- 【解决】建 `method_to_paper.json`（方法名→arxiv_id 权威映射）+ `PaperResolver`。

### 问题 14：指标库数据脏
- 【现象】查"BIT 的 F1"拿到一堆对比表 baseline（DTCDSCN、SNUNet…）和消融变体（+BIT S3、Base S4、32、16…）。
- 【根因】指标库抽取时**把对比表所有方法都抽了**，且没标出"本文方法"这一行。
- 【解决】从 eval_set_v9 的 gold 提取 30 条**干净的本文方法指标**（paper_metrics.json），插件优先查它。

### 问题 15：BIT/SNUNet/STANet 原论文不在语料
- 【现象】"BIT" 是方法名不是标题（标题是"Remote Sensing Image Change Detection with Transformers"）；SNUNet、STANet 原论文干脆不在 109 篇语料里。
- 【影响】"SNUNet 改进"这类概念题，只能靠别的论文引用的片段，答不好有部分是这个原因。
- 【解决】method_to_paper 里 SNUNet/STANet 标空（诚实标注"不在语料"）。

### 问题 16：8B 多专家会诊幻觉
- 【现象】Panel 4 视角中，综述派把 BIT 说成"早期基于 CVA 的方法"（错，BIT 是 Transformer 方法）。
- 【根因】4 个"专家"其实是同一个 8B 模型，知识混淆会暴露。
- 【解决】靠可插拔后端（LLMBackend）切更强模型缓解，8B 下只能接受。

## 六、通用工程问题（贯穿全程）

### 问题 17：`pkill -f` 自杀陷阱
- 【现象】`pkill -f "paperqa_concept.py 3"` 把自己也杀了。
- 【根因】`-f` 匹配的是完整命令行，命令里含脚本名会匹配到自己的 shell。
- 【解决】用 `pkill -f "[p]aperqa"` 括号技巧，或写成独立启动脚本 `exec` 调用。

### 问题 18：SSH 抽风
- 【现象】`Connection timed out during banner exchange` / `Failed to connect`，时断时续。
- 【解决】所有 SSH/scp 命令带重试循环。

### 问题 19：API key 硬编码泄露
- 【现象】仓库是 public，但多个 .py 文件硬编码了 key。
- 【解决】全部改环境变量读取（`OPENAI_API_KEY`），`.gitignore` 加 `.env`/`.mentor_env`/`secrets*` 隐藏，配 `.env.example` 模板。

### 问题 20：vLLM 加载慢误判就绪
- 【现象】curl `/v1/models` 通了就以为就绪，实际还在加载 safetensors（要 4-5 分钟）。
- 【解决】等 8000 端口真正监听（`ss -tlnp | grep :8000`）才算就绪。
