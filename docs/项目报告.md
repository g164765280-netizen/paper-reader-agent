# 领域文献阅读 Agent — 项目报告

> 面向研究生新生的领域文献阅读助手。目标：帮不熟悉领域的新生快速读懂文献、查指标、看影像、做跨论文综合。
> 这份报告完整记录技术路线、每一步碰到的问题、排查过程、解决方案和量化结果，可直接作为简历和面试的参考底稿。

---

> ⚠️ **评测更正声明（2026-09-10）**
>
> 早期版本报告中的「数字忠实 89.7% / 97.2%」存在**答案泄漏**：评测程序在"检索"阶段直接读取了标准答案（gold 的 field 和 number）去定位证据句子，属**含 gold 定位的受控实验**，不是真实检索。
>
> 因此这两个数字**作废**，不能作为对外结论，也不应写进简历。
>
> **真实有效的结果**：Oracle 79.8%（给对证据，测生成上限）、dense RAG 17.4%（真实检索），以及由两者对比得出的「检索是瓶颈」结论。其余数字见文末「评测修正附录」，标注了各自的可信度等级。

## 一、项目概述

**一句话**：从「检索增强问答（RAG）」开始，一路做到「知识图谱 + 多步推理的领域专家」，核心价值是一条可复现的工程闭环——**发现问题 → 定位原因 → 换思路 → 数据验证**。

**解决的真实痛点**：研究生新生进组后，领域不熟、论文读不懂、术语看不懂、实验不会分析。

**技术路线全貌**：

```
RAG 检索问答 → 评测先行(Oracle对照) → 数字感知检索 → 换模型
→ 微调(负结果) → 多模态(Qwen3-VL) → Agent + MCP → 知识图谱专家
```

**核心成果数据**：

| 能力 | 指标 | 结果 | 可信度 |
|---|---|---|---|
| 检索（真实 dense RAG） | 数字忠实 | **17.4%** | ✅ 有效 |
| 生成（Oracle 给对证据） | 数字忠实 | **79.8%** | ✅ 有效 |
| 检索召回（论文级） | — | 99.6% | ⚠️ 层级待修正（见附录） |
| 多模态变化检测 | 检出 / 定位 | 100% / 85% | ⚠️ 探索性（20 正样本，无负样本） |
| 知识图谱规模 | 109 篇论文 | 1182 实体 / 503 关系 | ✅ 有效 |
| 专家三套题评测 | 内化 / 综合 | 80% / 67% | ⚠️ 探索性（LLM-as-judge，单次） |

## 二、完整技术路线（按时间顺序，连起来的因果链）

### 第 1 步：起步 —— 先做 RAG，不做无评测的优化

**做了什么**：搭了一个检索增强问答系统——把 120 篇遥感变化检测论文喂进去，用户提问，系统检索相关段落，大模型基于段落回答。

**关键决策**：最初的设想是复刻微调链路（SFT/DPO/GRPO），但没一上来就微调。因为如果连"把信息找出来"都做不到，微调是空中楼阁。所以先做检索。

**碰到的第一个问题**：系统能回答，但**答对没有？错在哪？完全不知道**。答错有两种可能——① 检索没找到对的段落，② 段落找对了但模型没读对。两种错的优化方向相反，混在一起无法下手。

**排查方法（Oracle 对照）**：设计了对照实验，把两种错拆开——
- **Oracle 组**：不检索，直接把"正确答案所在句子"喂给模型 → 测模型的"读证据 + 抽答案"上限；
- **RAG 组**：让模型自己检索 → 测端到端效果。

**结果**：

| | 数字忠实（抽对具体数值） |
|---|---|
| Oracle（给对证据） | **79.8%** |
| RAG（自己检索） | **17.4%** |

**结论**：模型"读得懂"（79.8%），是"找不到"（17.4%）。**瓶颈在检索，不在生成。** 下一步优化检索。

> 附带教训：评测本身也踩了坑——最初金证据只截全文前 1600 字，导致 70% 数字题的"标准答案"根本不在证据里，测出假性 8%。这提醒：**评测的尺子必须先自证可靠，金证据必须真的含答案。**

### 第 2 步：优化检索 —— 分块对比 + 换范式

**碰到的第二个问题**：定位到检索不行，但"检索为什么不行"还不知道。第一猜测是**分块粒度**——块太大检索不精准，块太小丢上下文。

**排查方法（分块对比）**：做了三组分块实验。

| 分块方式 | 块数 | 数字忠实 |
|---|---|---|
| 段落级 | 1,354 | 17.4% |
| 句子级 | 27,977 | 17.8% |
| LlamaIndex 切块 | 7,683 | 19.7% |

**结果**：三种分块差了 20 倍，数字忠实却都卡在 17~20%。**排除分块原因。**

**进一步定位**：深挖后发现问题在**检索范式本身**——"这篇论文 F1 是多少"这类题，语料里有无数句"F1=0.90 / F1=0.85 / IoU=0.81"，它们的向量和关键词高度相似，朴素检索天然分不清哪个是目标。**这是检索的天花板，调参无用。**

**换思路（数字感知检索）**：既然检索走不通，就**不靠检索**——在索引阶段把每篇论文的"字段 → 数值 → 原文句子"结构化预提取成表，数字题直接查表命中。

**⚠️ 结果已作废**：早期实现里，评测程序直接用标准答案（gold 的 field 和 number）去查表定位句子，属**答案泄漏**，不是真实检索。因此 89.7% 作废。

> **思路本身仍成立**（结构化查表方向没错），但必须改用"从题目解析出的字段"而非 gold 字段来查表，且题目要先消除歧义（含方法/数据集/split）。这是后续要重做的评测。

### 第 3 步：换模型（⚠️ 数字部分作废）

**做了什么**：换更强的生成模型 Qwen3-8B。

**⚠️ 数字部分作废**：89.7%→97.2% 建立在泄漏评测上，不能对外用。

**名称/引用部分保留说明**：名称（58.6%→77.3%）、引用（54.4%→98.2%）走的是真实检索分支（非泄漏），但仍属**弱指标**——名称题命中任意一个就算对、引用只检查答案里有没有 `[n]`、名称 gold 来自正则提取可能有噪声。这些数字只能当参考，不能当"覆盖能力"或"引用正确率"。

**结论**：换模型方向仍需保留，但所有基于当前评测的数字都要在重建无泄漏评测后重测。

### 第 4 步：微调（一个诚实的负结果）

**做了什么**：完整跑了 SFT（50 步、200 步）、DPO、GRPO（强化学习，带规则奖励）。

**结果**：核心指标提升有限。

**原因判断**：① 合成数据难迁移到真实长文本任务；② 检索范式 + 换模型已解决瓶颈，微调边际收益小。

**结论**：这是一次有效的 **ablation（消融实验）**——证明了"不是所有任务都需要微调/RL"。**知道什么时候不该做什么，本身就是工程判断力。**

### 第 5 步：多模态（Qwen3-VL）

**做了什么**：加入视觉能力，让系统看单张遥感影像（描述地表类型）、看双时相影像（检测哪里变了）。

**碰到的第三个问题**：变化定位评测只有 40%。

**排查**：检查评测标准"变化区域质心是否匹配"，发现**是标准错了**——遥感变化是分散的（多处小建筑增删），质心落在"中心"，而模型描述的是"最明显那处变化"，模型没说错。

**处理**：换成公平标准"模型说的位置是否真有变化覆盖"。

**结果**：定位准确率 **40% → 85%**。

> 教训：**别用错误的标准冤枉模型，评测标准必须和"模型该干什么"对齐。**

### 第 6 步：Agent 化（工具 + MCP）

**做了什么**：把能力封装成工具（检索论文、查指标、看影像、测变化、写实验报告），让模型用 function-calling 自主决定调哪个工具，再用 MCP 协议把工具暴露成标准接口。

**价值**：从"写死的路由分发"升级到"模型自主决策调工具"。

### 第 7 步：从"检索玩具"到"知识图谱专家"

**碰到的第四个问题（最重要的反思）**：前面成果本质仍是"检索 + 抽取"——**它查得到，但没学会**。真正的专家应该是：不看论文也能答领域问题（知识内化）、能应用到新场景（推理）。

**重新定义差距**：

| | 检索玩具 | 专家 |
|---|---|---|
| 知识在哪 | 外部（临时抓片段） | 内部（内化了） |
| 关掉检索能答吗 | 不能 | 能 |
| 会做什么 | 抽取、引用、照抄 | 对比、推理、选型、跨论文综合 |

**处理**：换知识图谱 + 多步推理路线（底座用成熟开源项目 litkg-assistant，不重复造轮子），把论文提炼成"方法/数据集/指标/关系"的结构化图谱。

**结果**：109 篇论文 → **1182 实体 / 503 关系**，每个结论可溯源到"哪篇论文哪一页"，实现社区发现 + 全局综述问答（跨论文综合）。

### 第 8 步：专家评测（三套题）

**评测设计**：三套题对应"专家"的三个能力——知识内化（关掉检索答领域知识）、知识应用（新场景选型）、跨论文综合。

**结果**：

| 能力 | 得分 |
|---|---|
| 知识内化（关掉检索） | **4/5（80%）** |
| 知识应用（新场景选型） | 1/3（33%） |
| 跨论文综合 | **2/3（67%）** |
| **总计** | **7/15** |

**诚实结论**：实质跳出了检索玩具（关检索能答 80% 领域知识、67% 跨论文综合），但离"专家"还远；图谱信息不完整时会幻觉（如把 BIT 编成 "Binary Image Transform"，实际是 Bitemporal Image Transformer）。

## 三、踩过的坑（问题 → 排查 → 处理）

| 问题 | 排查 | 处理 |
|---|---|---|
| 实体抽取失败率高达 40% | 长论文 JSON 输出被截断 + 字段内特殊字符未转义 | 约束 JSON 输出格式 + token 上限 + 输入截断，失败率降到 <10% |
| 综述论文跑 10 分钟不结束 | 生成没有 token 上限，无限输出 | 加生成上限 |
| Qwen3 输出"污染"JSON | 默认带思考链，污染了纯 JSON | 换 Qwen2.5（或关思考模式） |
| 变化定位评测 40% | 评测标准"质心匹配"不公平 | 换"变化区域覆盖"，85% |
| 某篇论文抽到非法关系类型，整篇失败 | 枚举校验太严，一个坏关系拖垮全篇 | 跳过坏关系，不整篇失败 |

## 四、可直接参考的简历 bullets

1. 构建覆盖 120 篇遥感变化检测论文的全文级 RAG 问答系统，用 Oracle 对照（给对证据 79.8% vs 真实检索 17.4%）精确定位"数字抽取的瓶颈在检索不在生成"。
2. 通过段落/句子/LlamaIndex 三组分块对比实验，证伪"分块粒度是瓶颈"的假设。
3. 复刻 SFT/DPO/GRPO 对齐链路，诚实记录其边际收益，形成"何时不做微调"的判断。

5. 基于 litkg-assistant 构建 1182 实体 / 503 关系的可溯源知识图谱，实现社区发现与全局综述问答。

## 六、评测修正附录（来自代码审查）

### 数字有效性清点

| 数字 | 状态 | 说明 |
|---|---|---|
| Oracle 79.8% | ✅ 有效 | 真给 gold 证据，测生成上限 |
| dense RAG 17.4% | ✅ 有效 | 真实检索（bge+BM25+rerank） |
| 分块对比 17~20% | ✅ 有效 | 都是真实检索 |
| **89.7% / 97.2%** | ❌ 作废 | 评测用 gold 定位句子，答案泄漏 |
| 引用率 98.2% | ⚠️ 弱指标 | 只检查有无 `[n]`，不验证是否支撑结论 |
| 拒答率 100% | ⚠️ 弱指标 | 用 ZZZQWE123 假问题，关键词判断 |
| 名称 77.3% | ⚠️ 弱指标 | 命中任意一个就算对，gold 有噪声 |
| 变化检出 100% | ⚠️ 探索性 | 20 个正样本，无负样本 |
| 定位 85% | ⚠️ 探索性 | 文本象限，非 IoU/Dice |

### 已确认的 4 个评测问题

1. **答案泄漏**：检索分支读取 `gold["field"]` 和 `gold["number"]` 定位句子，等于 Oracle+答案。
2. **数字题歧义**：一篇论文有多个 F1（不同数据集/方法/split），但题目文本相同、答案不同。
3. **检索召回测错层级**：测的是"论文是否被召回"，而数字问答需要"含答案的句子是否被召回"（Document Recall ≠ Evidence Recall）。
4. **弱指标**：引用、拒答、名称、数字匹配的判定都过松，无多次运行/置信区间。

### 修复计划（按优先级）

1. 撤下 89.7%/97.2%（已做），标为"含 gold 定位的受控实验"。
2. 重建无泄漏数字题：题目含「方法 + 数据集 + split + 指标」。
3. 检索端只看用户问题，不访问 gold。
4. 拆分四指标：论文召回 / 证据召回 / 答案正确率 / 引用正确率。
5. VLM 加随机正负样本 + 盲测 + 空间定位指标（IoU/Dice/pointing）。
6. 建 Agent benchmark：工具选择 / 参数抽取 / 工具成功率 / 最终答案正确率。
7. 重写报告，分「已证实 / 探索性 / 待验证」。
