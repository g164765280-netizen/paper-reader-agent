## 1. 项目概述与架构

```
论文语料(arXiv 120篇摘要) ──> 分块 ──> BM25 + bge-m3向量(FAISS) ──> 混合检索 + bge-reranker重排
                                                                        │
问题 ───────────────────────────────────────────────────────────────> 证据 ──> Qwen2.5-7B ──> 带引用答案
                                                                        │
                                                  领域微调(SFT/DPO, LoRA r=8 + merge)
```

**核心分工**：RAG 提供证据、模型理解证据（两者都可能出错）；微调只改「怎么讲」（忠实抽取/引用/拒答），不改事实正确性。

## 3. 评测方法

- **留出论文隔离**：留出论文不进语料，避免同论文泄漏。
- **Oracle 对照**：`Base+正确证据` vs `Base+RAG`，分离「检索错误」与「生成错误」。
- **自动 heuristics**：拒答、名称/数据集覆盖、数字忠实、引用率（`[n]` 标注）。

## 6. 前后对比总结（修复后评测集）

| 指标 | Base | SFT v2(200步) | DPO(50步) | 结论 |
|---|---|---|---|---|
| 检索召回 | 100% | 100% | 100% | 检索不是瓶颈 |
| 拒答 | 100% | 100% | 100% | prompt 已足够 |
| 引用率(oracle) | 24.9% | **60.8%↑** | 69.3% | SFT v2 大幅提升引用 |
| 引用率(rag) | 13.8% | **56.6%↑** | 0.5% | DPO 过拟合 |
| 名称覆盖 | 65.1% | 61.9% | 52.4% | 引用提升轻微挤占名称 |

**核心发现**：
1. 检索端强（100% 召回），误差全在生成端。
2. **200 步 + 更难数据的 SFT v2 把引用率从 24.9%→60.8%（oracle）、13.8%→56.6%（rag）大幅拉起，且 RAG 模式下不再崩溃——这是可量化的正向前后变化。**
3. 代价：名称覆盖略降（65%→62%）。
4. 50 步 DPO 出现**引用行为过拟合**：给干净证据会引用（69%），给检索来的多段证据就几乎不引用（0.5%）。

## 7. 诚实结论与边界

1. **RAG 提供证据、模型理解证据，两者都可能出错**（不写「RAG 保证正确」）。
2. 微调提升「忠实/引用/拒答」等生成行为，不提升事实正确性（事实来自检索）。
3. 语料是**摘要级**，不是全文 PDF 解析（PDF 下载被 arXiv 限流）。
4. 自动评测是行为工程评测，不替代人工质量评审。
5. 「前景分析/综合」是综合论文观点，不是可靠逻辑推理。

## 10. 全文级升级与关键发现（2026-09-06 续）

### 10.1 全文级 RAG 基线（450 题，修复评测 bug 后）

| 指标 | Oracle(给对证据) | RAG(检索) |
|---|---|---|
| 检索召回(论文级) | — | **99.6%** |
| **数字忠实** | **79.8%**（170/213） | **17.4%**（37/213） |
| 名称 | 29.7% | 60.2% |
| 引用率 | 41.8% | 16.7% |
| 拒答 | 100% | 100% |

### 10.2 核心结论：检索"粒度"是真瓶颈

1. **生成端不弱**：给对证据（Oracle），基座模型抽数字达 **79.8%**。
2. **检索端是瓶颈**：RAG 能找到正确论文（99.6%），但**找不准"含数字那句话"**（数字忠实掉到 17.4%）。
3. **切块粒度不是解药**：句子级切块（27977 块）后数字仍 17.8%、名称反而降到 23.4%（丢上下文）。
4. **微调路线验证**：SFT(50/200步)/DPO/GRPO 均未能提升数字忠实——合成数据难以迁移到长文本精确抽取。

### 10.3 数字感知检索 + Qwen3-8B：最终结果

| 指标 | Qwen2.5-7B+稠密 | Qwen2.5-7B+数字感知 | **Qwen3-8B+数字感知** |
|---|---|---|---|
| 数字忠实 | 17.4% | 89.7% | **97.2%**（207/213） |
| 名称 | 60.2% | 58.6% | **77.3%**（99/128） |
| 引用率 | 16.7% | 54.4% | **98.2%** |
| 拒答 | 100% | 100% | 100% |
| 检索召回 | 99.6% | 99.2% | 99.2% |

两步提升：
1. **数字感知检索**（结构化指标提取+查表）→ 数字 17.4%→89.7%。
2. **换 Qwen3-8B**（新一代模型，yjl 目录里现成）→ 数字 97.2%、名称 77.3%、引用 98.2%。

**完整简历叙事**：
> 构建全文级 RAG（120 篇论文，检索召回 99.6%）→ Oracle 对照定位"数字忠实仅 17%、瓶颈在检索粒度" → 实现数字感知检索（结构化指标提取+查表）提升到 89.7% → 升级 Qwen3-8B 后数字 97.2%、名称 77.3%、引用 98.2%。

### 10.4 诚实边界

- "字段-数字-单位"的精确抽取是全文级 RAG 的真实难点：问题只给"F1 是多少"，但"F1=0.90 / F1=0.85 / IoU=0.81"等句子的向量高度相似，朴素检索分不清。
- 这需要**数字感知检索**（索引数字提及、多跳检索：先定位论文→再定位指标句），是后续工作，不是调参能解决的。

### 10.4 评测 harness 本身的价值

评测过程中发现并修复了一个关键 bug：金证据最初只截全文前 1600 字符，导致 70% 数字题的 gold 数字根本不在证据里（假性"数字忠实 8%"）。修复后（金证据=含指标的那句话）得到真实基线 79.8%。这个"金证据必须含答案"的评测方法论本身就可写进简历。

## 11. 多模态（Qwen3-VL）：遥感影像理解

### 11.1 环境打通

- 发现 `/media/sdb1/yjl/ollama-models/` 下的模型实为 **Transformers 格式**（非 Ollama GGUF），可直接用 `AutoModelForImageTextToText` 加载，无需 Ollama。
- Qwen3-VL-8B 已跑通，能看遥感影像。

### 11.2 已验证的两项能力

| 能力 | 测试 | 结果 |
|---|---|---|
| 单时相影像描述 | LEVIR-CD 影像 → "描述地表类型" | ✅ 准确识别道路/建筑/植被/水体 |
| 双时相变化检测 | T1+T2 两期影像 → "哪里变了" | ✅ 准确指出"高速公路扩建、新增车道、树林被施工取代" |

### 11.3 定位与边界

- Qwen3-VL 的定位是"把影像/变化**翻译成语言**"，**不是替代 ChangeFormer 做像素级检测**（像素级仍是专用 CD 模型）。
- 后续方向：变化图解读 → 自动写实验报告（对接你的 CD 工作流）、多模态 RAG（影像 + 论文融合）。

## 12. Agent + MCP + 多模态融合（遥感 RAG Agent 小助手）

### 12.1 架构

```
问题(+可选影像)
  ├─ 2张影像 → detect_change（双时相变化检测）
  ├─ 1张影像 → analyze_image（影像描述/解读）
  └─ 无影像  → search_papers（文本 RAG 检索论文）
融合：fuse = 检索论文知识 + 看影像 → Qwen3-VL 综合解读
```

### 12.2 工具（6 个，已通过 MCP 协议暴露）

| 工具 | 作用 | 模型 |
|---|---|---|
| search_papers | 检索论文回答文本问题 | Qwen3-8B + RAG |
| lookup_metric | 查论文指标数字 | 结构化查表 |
| analyze_image | 描述/解读单张影像 | Qwen3-VL |
| detect_change | 双时相变化检测 | Qwen3-VL |
| fuse | 论文知识 + 影像融合解读 | Qwen3-VL |
| **generate_report** | **变化图 → 自动实验报告** | Qwen3-VL |

### 12.3 验证

- 路由式融合 ✅：文本问答 / 影像描述 / 变化检测 三条路径均跑通。
- MCP server ✅：`mcp_server.py` 通过 MCP v1（FastMCP）暴露 6 个工具。
- 实验报告 ✅：输入变化图 + 指标 → 自动生成"总体结论/指标解读/空间变化/误差诊断/改进建议"完整报告。

### 12.4 自主 tool-calling + Qwen3-VL 评测

**自主 tool-calling agent**（`agent_toolcall.py`）：Qwen3-8B 用 function-calling 自主决定调用哪个工具，多轮循环直到给出最终回答（已验证 search_papers 路由）。

**Qwen3-VL 变化检测系统评测**（LEVIR-CD 测试集，20 场景，GT 对照）：

| 指标 | 结果 | 解读 |
|---|---|---|
| 变化检出率 | **100%**（20/20） | 可靠判断"有无变化" |
| 定位准确率 | **85%**（17/20） | 用"变化区域覆盖"评判（模型说的象限是否有变化），粗粒度定位可靠；质心匹配则 40%（过严） |
