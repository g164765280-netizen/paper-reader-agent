# 概念题评测报告（PaperQA2 流程）

> 对应 `docs/概念题交接文档.md` 第四节。数字题通路见 `docs/数字题评测报告.md`。

## 概览

- 答题模型：**本地 Qwen3-8B**（vLLM 起服务 `:8000`，免费；`enable_thinking=False` 关思考）
- 检索/证据层：**PaperQA2**（paper-qa 2026.8.12 + litellm）
- embedding：**本地 bge-m3**（sentence-transformers，CPU）
- 语料：**109 篇**论文全文（fulltext JSON 的 `pages_text`，约 6.0M 字符，切成 1261 个 chunk）
- 题目数：**50 道概念题**（扩库自 `导师评测基准30题.md` + `遥感方法知识地图.md`，含金标准关键点）
- 评分：**LLM-as-judge**（API `qwen3.8-max`，独立第三方，避免自评）

## 三维评分指标（白话解释）

| 维度 | 白话 | 测的是谁 |
|---|---|---|
| **grounded（有出处）** | 答案引用的论文段落**真的对得上**、不瞎编 | 检索的准不准 |
| **relevance（答到点）** | 答案**到底答没答对** | 模型理解能力强不强 |
| **honesty（诚实）** | 不知道时有没有**老实说"查不到"** | 模型诚不诚实 |

> 关键：grounded + honesty 是**检索层的功劳**；relevance 是**模型（8B）的理解能力**。两者要分开看。

## 四个版本演进（v1 → v4）

| 版本 | 关键改动 | grounded | relevance | honesty | 结论 |
|---|---|---|---|---|---|
| v1 | 原始流程（20 题） | 95% | 75% | 90% | 基线 |
| v2 | 扩库 50 题 + RAG 调参（cutoff+消歧 prompt） | **100%** | 74% | **96%** | 检索干净 |
| v3 | +注入权威概念词条（31 条） | 98% | 76% | **96%** | **最终采用版** ✅ |
| v4 | 关摘要（evidence_skip_summary）+ 直读原文 | 14% ❌ | **84%** | 14% ❌ | 已探索，**不采用** |

### 各版本做了什么、查出什么

**v1（基线）**：原始 PaperQA2 流程跑通，20 题。发现 grounded 95% 不错，但 relevance 上不去，开始排查。

**v2（扩库 + RAG 调参）**：题库 20→50 题，覆盖知识地图全部章节。RAG 层三处修复——
1. `evidence_relevance_score_cutoff: 1→3`（过滤弱相关 chunk）
2. qa prompt 强化「先给本质定义 + 同名实体消歧」
3. system prompt 强化「歧义词先定义」

修好了 3 道典型错题的「同名实体污染 / 引用错位」。grounded 冲到 100%。

**v3（注入权威词条）**：把 `data/resources/concepts.json` 里筛出的 **31 条**权威概念词条（有来源+可验证+无待查证）拼成一份文档 aadd 进语料。**这是最终采用版**——grounded 98%、honesty 96%、relevance 76%。

**v4（关摘要）**：把 paperqa 的 summary 环节关掉，让 8B 直读原文。relevance 冲到 84%（因为绕过了「8B 摘要写反术语」这个坑），**但 grounded 崩到 14%**——关摘要后丢失了「相关度打分过滤」，无关 chunk 混进引用，检索环节反而坏了。**已探索、结论：不可用（丢了 RAG 的灵魂——可追溯引用）。**

## 最终结论（当前采用 v3）

### ✅ 已经完成的（RAG 检索层可用）

- **grounded 98%**：引用干净、可追溯、不瞎编——这是 RAG 的核心价值，已达标。
- **honesty 96%**：信息不足时不瞎编。
- **检索环节本身没问题**：能找到对的段落、引得对、不编造。

### ⚠️ 还差的（模型理解层）

- **relevance 76%**：剩 24% 的题「答不到点上」。
- 这个瓶颈**不在 RAG，在本地 Qwen3-8B 的理解能力**，典型表现：
  - 「Precision/Recall、漏检/误报」这种成对概念的语义映射**会答反**（cq39/cq40）
  - 多关键点题**覆盖不全**（金标准 3 个点只答中 1–2 个）
  - 个别问题理解偏（cq34 数据增强题去讲配准）

### 一句话结论

> **RAG 检索层：完成、可用（grounded 98% / honesty 96%）。**
> **概念理解正确率：76%，瓶颈在本地 8B 模型，不在检索。**
> 下一步若要提 relevance，方向是**换更强的本地模型**（Qwen3-14B/32B 或 Qwen2.5-72B 量化版），不是继续调 RAG。

## 关键实现要点（避坑，供后续复用）

1. **aadd 必须传文件路径**（`.txt`），不能直接传文本字符串——否则 `md5sum(path)` 和 `read_doc` 都会失败（Errno36 文件名过长）。
2. **aadd 也要传 settings**，且 `Settings(llm=...)` 之外还要设 `summary_llm`（默认仍是 gpt-4o，会报"Missing credentials"）。
3. **本地 vLLM 关思考**：`litellm_params` 里加 `"extra_body": {"chat_template_kwargs": {"enable_thinking": False}}`，否则 Qwen3 思考污染答案。
4. **contexts 提取字段**：paperqa 2026.8.12 的 `Context` 顶层是 `id`(pqac-xxx)/`context`(文本)/`text`(Text 对象)/`score`，引用标记 `pqac-xxx` 对应 `Context.id`，论文出处从 `ctx.text.doc.citation` / `ctx.text.name` 取。
5. **judge 不能截断 contexts**：应按答案里实际引用的 pqac-id/chunk 名过滤后再传给 judge，否则误判"编造引用"。chunk 名匹配正则需要兼容 `authoritative_concepts chunk N` 这种非-arxiv 命名。
6. **关摘要的教训**：`evidence_skip_summary=True` 会让 relevance 升但 grounded 崩（丢失相关度过滤），**不可单独用**。摘要环节同时承担「压缩」+「打分过滤」两个功能，关掉后者要先补一个独立的非 LLM 重排过滤。
7. **pkill -f 自杀陷阱**：命令行含脚本名时 `pkill -f xxx` 会杀掉自己，用 `[x]xx` 括号技巧或写成独立启动脚本 `exec` 调用。SSH 抽风要带重试。
