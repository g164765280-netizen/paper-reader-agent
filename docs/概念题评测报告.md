# 概念题评测报告（PaperQA2 流程）

> 对应 `docs/概念题交接文档.md` 第四节。数字题通路见 `docs/数字题评测报告.md`。

## 概览

- 答题模型：**本地 Qwen3-8B**（vLLM 起服务 `:8000`，免费；`enable_thinking=False` 关思考）
- 检索/证据层：**PaperQA2**（paper-qa 2026.8.12 + litellm）
- embedding：**本地 bge-m3**（sentence-transformers，CPU）
- 语料：**109 篇**论文全文（fulltext JSON 的 `pages_text`，约 6.0M 字符，切成 1261 个 chunk）
- 题目数：**50 道概念题**（v2，扩库自 `导师评测基准30题.md` + `遥感方法知识地图.md`，含金标准关键点）
- 评分：**LLM-as-judge**（API `qwen3.8-max`，独立第三方，避免自评）

## 三维评分结果（v2，50 题）

| 维度 | 定义 | 得分 | 比例 |
|---|---|---|---|
| grounded（有出处） | 回答是否建立在真实引用论文段落之上，不编造 | 50/50 | **100.0%** |
| relevance（答到点） | 是否命中金标准关键点 | 37/50 | **74.0%** |
| honesty（诚实） | 信息不足时是否诚实，不瞎编 | 48/50 | **96.0%** |

## v1 → v2 变化对照（RAG 层修复效果）

| 指标 | v1（20 题） | v2（50 题） | 结论 |
|---|---|---|---|
| grounded | 95% | **100%** | ✅ 引用零编造 |
| relevance | 75% | **74%** | ≈持平（未突破） |
| honesty | 90% | **96%** | ✅ 提升 |

### RAG 层修复（v2 相对 v1 的改动，全部落在检索/prompt 层，答题模型仍是本地 8B）

1. **提高证据相关度阈值** `evidence_relevance_score_cutoff: 1→3`：过滤弱相关/消融实验类干扰 chunk。
2. **强化 qa prompt**：要求"先给本质定义""同名实体先消歧（取遥感变化检测语境）""只答概念不堆细节"。
3. **强化 system prompt**：歧义/缩写词先定义。

### 修复验证（3 道典型错题）

| 题 | v1 | v2 | 根因 |
|---|---|---|---|
| cq09 弱监督用什么标注 | ✘ 答"单日期语义标注" | ✅ 答"图像级/非像素级" | prompt 强化 |
| cq12 SECOND vs LEVIR-CD | ✘ 混淆成 3D 点云检测模型 | ✅ 正确区分 SCD/BCD，明确 SECOND 是数据集 | 消歧 prompt + cutoff |
| cq14 配准误差后果 | ✘ 引用失实（grounded 也 0） | ✅ 引用真实（grounded=1），但仍未点"伪变化" | cutoff 过滤干扰证据 |

## 剩余短板（relevance 74%，13 题未答到点）

分类后可见两类本质不同的失败：

### A 类：方向错误/理解偏差（更严重，4 题）

| 题 | 问题 |
|---|---|
| cq39 | 把"Recall 低 = 漏检"答反成"偏重减少误报"—— 纯知识反了 |
| cq43 | 把"检索/生成"答成"图像分析模块/问答生成模块"，没懂 RAG 基本概念 |
| cq34 | 数据增强题去讲配准了 —— 问题理解偏 |
| cq32 | WHU-CD/LEVIR-CD 分辨率优劣判断反了 |

### B 类：多关键点覆盖不全（9 题，方向对但漏点）

cq03、cq06、cq10、cq13、cq14、cq24、cq26、cq31、cq33、cq45 等 —— 金标准列 3 个点，8B 只命中 1–2 个。

## 结论

**RAG 层修复成功且到顶了**：grounded 100%（引用零编造）、honesty 96%、同名歧义与引用错位两类硬伤被 prompt + 阈值修复。

**relevance 74% 是本地 Qwen3-8B 的知识精确度天花板**，剩余错误集中在：
- 常识/已知结论答反（cq39/cq43/cq32）
- 多关键点覆盖不全（B 类 9 题）
- 个别问题理解偏（cq34）

这些属于"模型懂了但没懂透"，是 8B 能力边界，不是 RAG 通路问题。若需 relevance 突破 80%+，方向不是继续调 prompt，而是换更强本地模型（如 Qwen3-14B/32B 或 Qwen2.5-72B 量化版）或对评测集做更细的 prompt 工程。

## 关键实现要点（避坑，供后续复用）

1. **aadd 必须传文件路径**（`.txt`），不能直接传文本字符串——否则 `md5sum(path)` 和 `read_doc` 都会失败（Errno36 文件名过长）。
2. **aadd 也要传 settings**，且 `Settings(llm=...)` 之外还要设 `summary_llm`（默认仍是 gpt-4o，会报"Missing credentials"）。
3. **本地 vLLM 关思考**：`litellm_params` 里加 `"extra_body": {"chat_template_kwargs": {"enable_thinking": False}}`，否则 Qwen3 思考污染答案。
4. **contexts 提取字段**：paperqa 2026.8.12 的 `Context` 顶层是 `id`(pqac-xxx)/`context`(文本)/`text`(Text 对象)/`score`，引用标记 `pqac-xxx` 对应 `Context.id`，论文出处从 `ctx.text.doc.citation` / `ctx.text.name` 取。
5. **judge 不能截断 contexts**：应按答案里实际引用的 pqac-id/chunk 名过滤后再传给 judge，否则误判"编造引用"。
6. **pkill -f 自杀陷阱**：命令行含脚本名时 `pkill -f xxx` 会杀掉自己，用 `[x]xx` 括号技巧或写成独立启动脚本 `exec` 调用。
