# 人格层（Persona Layer）设计文档 —— 对话式领域专家

> 目标：让用户通过**自然对话**深入理解遥感变化检测领域。
> 架构延续「一切皆插件」：人格 = 可插拔的对话角色，叠加在多轮对话骨架之上。

---

## 一、核心定位

用户问 → 专家人格答 → 用户追问 → 专家查论文再答 → 越聊越深。

关键：**不是一次性报告**（那是 Tree-of-Debate 的产出），而是**多轮对话 + 按需召唤人格**。

## 二、人格层架构（三层人格）

```
┌─────────────────────────────────────────────┐
│  对话入口（多轮，记住上下文）                    │
│    ┌──────────────────────────────────────┐ │
│    │ 人格池（Persona Pool）                 │ │
│    │  1. 导师 Tutor        （常驻）         │ │
│    │  2. 多专家 Panel      （按需召唤，会诊） │ │
│    │  3. 创见 Ideator      （按需召唤）      │ │
│    └──────────────────────────────────────┘ │
│    ┌──────────────────────────────────────┐ │
│    │ 能力插件（复用已完成）                   │ │
│    │  lookup_metric / answer_concept /     │ │
│    │  summarize_compare                    │ │
│    └──────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

## 三、三个人格定义

### 1. 导师（Tutor）—— 常驻，默认人格

- **角色**：一个懂遥感变化检测的专家导师，负责普通问答、概念解释、读论文。
- **能力**：复用已完成的插件（数字题查指标、概念题 RAG、归纳对比）。
- **多轮记忆**：记住用户水平、目标、聊过什么，不重复讲。
- **触发**：默认就是它，无需召唤。

### 2. 多专家会诊（Panel）—— 遇到"对比/争议/选择"时召唤

- **角色**：4 个视角专家 + 1 个主持人。
  - 方法派：只看"方法设计思路"
  - 指标派：只看"实验结果数据"
  - 综述派：看"领域演进脉络"
  - 质疑派：挑刺、找反例
  - 主持人：汇总，给结论
- **触发**：用户问"XX 和 YY 哪个好 / 为什么 / 有什么区别"这类需要多视角的问题。
- **借鉴**：Tree-of-Debate 的 persona 思想，但**简化为单轮会诊**（不搞完整辩论树，够用为先）。

### 3. 创见（Ideator）—— 用户要"新思路/还能怎么做"时召唤

- **角色**：发挥 LLM 基模创造力，基于当前领域现状提新解决思路。
- **触发**：用户问"还能怎么改进 / 有什么新方向 / 如果换一种思路"。
- **借鉴**：AI co-scientist 的假设生成 + 迭代反馈。

## 四、人格怎么实现（一切皆插件）

每个人格 = 一个 **Persona 插件**，复用已有 Plugin 契约：

```python
class Persona:
    name: str                    # "tutor" / "panel" / "ideator"
    system_prompt: str           # 人格的系统提示词（决定"它是谁"）
    can_activate(context) -> float  # 判断该不该激活（类似 can_handle）
    respond(history, question) -> str  # 生成回答（可调工具）
```

**调度器升级**：原来的 Router 管"能力分流"，现在加一层 **Persona 调度**——
- 普通问题 → Tutor
- 对比/争议 → Panel
- 求新思路 → Ideator

两层关系：
```
用户问题 → 人格调度(选 persona) → 人格内部再调能力插件(查指标/检索/归纳)
```

## 五、关键设计决策（需用户确认）

1. **人格的 LLM 引擎**：沿用可插拔 LLMBackend（本地 8B / API 切换）。
2. **Panel 的深度**：先做"单轮会诊"（4 专家各发言一次 + 主持人汇总），不先做 ToD 的完整辩论树（那是后续增强）。
3. **多轮记忆**：复用 agent_toolcall 的 history 机制，但把 system prompt 换成人格的。

## 六、落地顺序

| 步骤 | 内容 | 依赖 |
|---|---|---|
| S1 | 定义 Persona 契约（含 system_prompt + 调度） | 已有 Plugin 契约 |
| S2 | Tutor 人格（接已有 3 个能力插件） | S1 |
| S3 | 对话入口（多轮 + 人格调度） | S2 |
| S4 | Panel 多专家会诊（4 视角 + 主持人） | S2 |
| S5 | Ideator 创见 | S2 |

## 七、验收标准（做完什么样算成）

1. 用户问「BIT 的 F1 是多少」→ 数字题答对（Tutor 调 lookup_metric）。
2. 用户问「为什么不用 OA」→ 概念题带出处答对（Tutor 调 answer_concept）。
3. 用户问「BIT 和 ChangeFormer 哪个好」→ **触发 Panel**，4 视角 + 主持人给结论。
4. 用户追问 → 记住上下文，接着聊。
5. 用户问「还能怎么改进」→ **触发 Ideator**，给新思路。
