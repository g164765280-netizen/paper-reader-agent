# 简历与面试（针对实习求职）

## 一、简历项目描述（可直接用）

**项目名**：领域文献速读 Agent（以遥感变化检测为例）

**一句话**：构建了一个面向研究生新生的领域文献速读 Agent，能论文问答、查指标、看影像、测变化、自动写实验报告，支持自主工具调用与 MCP。

**三条 bullets**：

- 基于 Qwen3-8B、bge-m3、FAISS 与 BM25 混合检索，构建覆盖 120 篇遥感变化检测论文的全文级 RAG 系统，检索召回 99.6%、数字忠实 97.2%、引用率 98.2%。
- 设计"留出论文隔离 + Oracle 对照"评测，分离检索误差与生成误差，定位出"数字忠实仅 17%、瓶颈在检索粒度"，并通过数字感知检索（结构化指标提取+查表）提升到 97.2%。
- 复刻 SFT/DPO/GRPO 对齐链路，接入 Qwen3-VL 多模态（变化检出 100%、定位 85%），用 function-calling 实现自主工具调用，并用 MCP 协议暴露 6 个工具。

## 二、技术栈

`Python · PyTorch · Transformers · PEFT · TRL · FAISS · BM25 · bge-m3 · Qwen3-8B · Qwen3-VL · MCP`

## 三、高频面试问题 + 参考回答

### Q1：为什么用 RAG 而不是直接微调？

微调学的是"生成行为"，不保证"事实正确"；RAG 提供证据让模型有据可依、能溯源。两者结合：RAG 管事实，微调管表达。本项目实测：检索召回 99.6%，但生成端精确抽数字只有 17%（给对证据能到 79.8%），说明瓶颈在检索不在生成。

### Q2：你的评测怎么做的？

"留出论文隔离"（测试论文不进语料，避免泄漏）+ "Oracle 对照"（给正确证据 vs 检索证据，分离检索错误和生成错误）。还踩过一个坑：金证据必须含答案，否则测的是假能力。

### Q3：数字忠实 17% → 97.2% 怎么做到的？

先定位根因：Oracle 对照发现生成端不弱（79.8%），是稠密检索找不到"含数字那句话"。解法：数字感知检索——把每篇论文的"字段→数字→句子"结构化提取出来，数字题直接查表，不靠稠密检索猜。再换 Qwen3-8B 进一步提到 97.2%。

### Q4：SFT/DPO/GRPO 你都做了，效果如何？

诚实说：50/200 步 SFT、DPO、GRPO 对核心指标提升有限，DPO 还出现引用行为过拟合。这本身是有效的 ablation 结论——不是所有任务都需要 RL，当检索+模型升级已解决瓶颈时，RL 边际收益很小。

### Q5：多模态（Qwen3-VL）的定位？

VLM 负责"把影像/变化翻译成语言"（描述、变化检测、写报告），不是替代 ChangeFormer 做像素级检测。评测：变化检出 100%、定位 85%（用"变化区域覆盖"评判）。

### Q6：为什么用 MCP？

工具协议化，让 agent 的能力可被任意 MCP 客户端调用，而不是写死在某个框架里。这是 agent 可复用、可集成的关键。

## 四、面试时别踩的坑（诚实边界）

- 别说"RAG 保证正确"——是"RAG 提供证据、模型理解证据，两者都可能错"。
- 别说"打造了专家/可靠推理"——是"领域行为工程评测，不声称可靠推理专家"。
- 别说"提升了医疗/遥感准确率"——没有专家 gold set，只有工程指标。
- 数字要能对得上、能复现（本项目所有结果都在 `docs/项目报告.md` 有据可查）。

## 五、一页纸自述模板

> 我做的是面向研究生新生的领域文献速读 Agent。先建全文级 RAG（检索召回 99.6%），再用 Oracle 对照定位出"数字抽取是瓶颈"（17%），通过数字感知检索+换 Qwen3-8B 提到 97.2%。过程中复刻了 SFT/DPO/GRPO，接入 Qwen3-VL 做多模态，最后用 tool-calling + MCP 把它做成可复用的 agent。最有价值的不是某个数字，而是这套"发现问题→定位根因→针对性解决"的完整闭环。
