# 研究想法迭代模块（借用 ResearchAgent）

> 这是"遥感科研导师"在"帮助用户做研究"这一侧的能力：当用户 goal=choose_method / improve_method / write_paper 时，导师不只是答疑，还能帮他**生成研究想法 → 设计方法 → 设计实验 → 多维度评审 → 迭代改进**。
> 直接借用 ResearchAgent（NAACL 2025）的结构，不用重写。

---

## 一、借用的核心：三阶段 + 各自多维度评审 + 迭代

ResearchAgent 的闭环（已实测其代码结构）：

```
核心论文
  → 检索相关工作 + 知识实体
  → ① 问题识别（Problem Identifier）：生成研究问题 + 理由
       → 问题评审（5 维）：Clarity 清晰 / Relevance 相关 / Originality 原创 / Feasibility 可行 / Significance 重要
       → 根据低分项迭代改进
  → ② 方法开发（Method Developer）：提出方法
       → 方法评审（5 维）：Clarity / Validity 有效 / Rigorousness 严谨 / Innovativeness 创新 / Generalizability 泛化
  → ③ 实验设计（Experiment Designer）：设计实验
       → 实验评审（5 维）
  → 输出：经过评审迭代的研究方案
```

**关键机制（最有价值）**：每个阶段的"评审"是**多维度、并行的 1-5 打分 + 结构化反馈**，然后**只针对低分项迭代**，而不是盲目重生成。这保证了产出的研究想法是有质量约束的，不是"随口一说"。

---

## 二、我们怎么借用（适配遥感）

| ResearchAgent 原版 | 我们的适配 |
|---|---|
| 输入：Semantic Scholar 论文 ID | 输入：用户的遥感问题 + 方法知识地图 + PaperQA2 证据 |
| 知识实体：通用实体库 | 用**遥感方法知识地图**做领域约束（方法/数据集/指标/难点） |
| GPT-4o | 强模型（Claude/本地大模型），稳定后蒸馏 |
| 通用科研问题 | **遥感专属**：评审时注入遥感约束（配准、类别不平衡、小目标、监督方式） |

**评审维度增加遥感专属约束**：
- 问题评审的 Feasibility（可行性）里，加入"是否考虑了配准误差""数据标注成本"。
- 方法评审的 Validity（有效性）里，加入"指标选择是否合理（不能用 OA 当主指标）""是否处理类别不平衡"。
- 实验评审里，加入"是否设了正确的基准""是否含无变化负样本"。

---

## 三、在导师流程里的位置

```
用户问题 → 问题理解器（九元组）
  → goal=improve_method / write_paper
  → 研究想法迭代模块（本文档）
        ├─ 问题识别 + 5 维评审 + 迭代
        ├─ 方法开发 + 5 维评审 + 迭代
        └─ 实验设计 + 5 维评审 + 迭代
  → 输出：可执行的研究方案（含遥感约束）
```

---

## 四、落地方式

- 直接抽 ResearchAgent 的 6 个 agent 提示词（problem_identifier / problem_validator / method_developer / method_validator / experiment_designer / experiment_validator），**保留 5 维评审结构**，把领域约束注入到评审 prompt 里。
- 不需要重新训练，用强模型跑 prompt 即可。
- 评测：用"研究方案是否含正确约束、是否可执行、是否针对低分项迭代"来打分（复用 `导师评测设计.md` 的思路，但侧重"研究建议质量"）。

---

*诚实边界：ResearchAgent 是通用科研想法生成，我们对遥感约束的注入是增量；评审的 5 维标准是借用，遥感专属约束需在真实使用中迭代。*
