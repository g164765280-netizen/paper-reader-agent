# 最近进展说明（诚实版）

> 写这个文档是因为：最近的工作方向偏离了，RAG 本身没解决，却在提示词工程上打转。这里如实记录。

---

## 一、最初要解决的问题（RAG）

帮研究生新生做"论文数字问答"：问"论文 X 在 LEVIR-CD 上的 F1 是多少"，系统要从论文库里**检索**出含答案的句子，再抽数字回答。

## 二、RAG 现在的真实水平（没解决）

| 指标 | 真实值 |
|---|---|
| 论文召回率（找到正确的论文） | **47.9%** |
| 证据召回率（找到含答案的句子） | **38.0%** |
| 答案正确率 | **45.1%** |
| （对照）给对证据的上限 | 86.6% |

**两个病根**：
1. **论文标题没进分块的文本里** → 问题里的"论文《XXX》"没法帮检索定位论文，所以论文召回只有 48%。
2. **数字句太像**（"F1=0.90" vs "F1=0.85"）→ 检索分不清，证据召回只有 38%。

## 三、我走偏的地方（诚实）

1. **"数字感知检索"声称 17.4%→97.2%，是假的**——代码读了标准答案（gold）去定位句子，等于作弊。真实是 45.1%。
2. **"导师 agent"本质是提示词工程**——靠模型（qwen3.8-flash）自己已有的知识 + 提示词里 4 行领域知识，直接答题，**根本没走检索**。它 95% 的分数是模型本来就会，不是 RAG 的能力。

**结论：RAG 检索这个核心问题，我一直没真正解决，反而绕开它去搞了提示词工程。这是方向错误。**

## 四、接下来要做的（回正）

重新认真做 RAG，两个对症的修法：

1. **标题→论文 ID 解析**：把每篇论文的标题和 ID 建映射，问题里的标题能直接定位论文（修论文召回 48% 的病灶）。
2. **结构化指标表（不偷看答案）**：预先从论文里抽出"指标→数值→数据集→句子"，数字题解析题目（不是读 gold）后查表定位句子（修证据召回 38% 的病灶）。

目标：把答案正确率从 45.1% 拉上去，且**评测无泄漏**。
