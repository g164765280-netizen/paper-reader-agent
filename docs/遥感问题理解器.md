# 遥感问题理解器（Question Understander）

> 这是"遥感科研导师"的第一个专属增量：把用户的一句自然语言问题，结构化成一个**九元组**，让导师知道用户到底在问什么、该走哪条知识路线、用哪个 NORA 技能。
> NORA 本身不做这个（它假设用户直接给研究方向），这是我们要补的教学入口。

---

## 一、为什么需要它

新手的问题往往是模糊的、混在一起的。比如：

- "我想做变化检测" → 这到底是要**理解概念**、还是要**选方法**、还是要**复现**？监督方式？模态？完全没说。
- "我的模型 F1 很低怎么办" → 这是**改进方法**，但没说是什么场景、什么难点。

如果导师直接回答，要么答偏，要么答得太浅。所以**第一步必须先结构化**，把模糊问题拆成明确的九元组，再决定怎么教。

---

## 二、九元组定义

| 字段 | 取值（枚举） | 说明 |
|---|---|---|
| **领域 domain** | 变化检测 / 语义分割 / 目标检测 / 图像分类 / 超分重建 / 其他 | 大方向 |
| **任务 task** | 自由文本 | 具体任务描述 |
| **场景 scenario** | 建筑 / 植被 / 水体 / 城市 / 农田 / 冰雪 / 其他 / 未指定 | 地表类型 |
| **模态 modality** | 光学 / SAR / 多光谱 / 高光谱 / LiDAR / 多模态 / 未指定 | 数据源 |
| **监督 supervision** | 全监督 / 半监督 / 无监督 / 弱监督 / 跨域 / 开放词汇 / 未指定 | 标注情况 |
| **输入 input** | 双时相 / 单时相 / 时序序列 / 未指定 | 输入形态 |
| **输出 output** | 二值变化图 / 语义变化图 / 变化描述文本 / 未指定 | 输出形态 |
| **难点 difficulty** | 小目标 / 类别不平衡 / 配准误差 / 云遮挡 / 伪变化 / 算力受限 / 未指定 | 用户卡点 |
| **指标 metric** | F1 / IoU / OA / Precision / Recall / 未指定 | 关注什么 |
| **目的 goal** | 理解概念 / 选方法 / 复现论文 / 改进方法 / 读文献 / 写论文 / 其他 | 用户真正想干什么 |

> 关键：**"目的"是路由的核心**。同样的问题，goal=理解概念 和 goal=改进方法，导师的答法完全不同。

---

## 三、结构化提示词（供导师 agent 调用）

```
你是遥感科研导师的"问题理解器"。把用户的问题结构化成一个 JSON 九元组。
只输出 JSON，不要解释。

字段（全部为字符串，枚举值用英文小写）：
- domain: change_detection / semantic_segmentation / object_detection / image_classification / super_resolution / other
- task: 一句话任务描述（中文）
- scenario: building / vegetation / water / urban / farmland / snow / other / unspecified
- modality: optical / sar / multispectral / hyperspectral / lidar / multimodal / unspecified
- supervision: fully_supervised / semi_supervised / unsupervised / weakly_supervised / cross_domain / open_vocabulary / unspecified
- input: bitemporal / single_temporal / time_series / unspecified
- output: binary_change_map / semantic_change_map / change_caption / unspecified
- difficulty: small_object / class_imbalance / registration / cloud / pseudo_change / compute / unspecified
- metric: f1 / iou / oa / precision / recall / unspecified
- goal: understand_concept / choose_method / reproduce / improve_method / literature_review / write_paper / other

规则：
1. 用户没说清的就填 unspecified，不要猜。
2. goal 是最重要的字段，必须从用户意图推断。
3. 如果一句话里混了多个意图，取最主要的那个 goal。
```

## 四、少样本示例

**例 1**：用户："变化检测用什么指标评估？"
```json
{"domain":"change_detection","task":"变化检测评估指标","scenario":"unspecified","modality":"unspecified","supervision":"unspecified","input":"unspecified","output":"unspecified","difficulty":"unspecified","metric":"unspecified","goal":"understand_concept"}
```
→ 路由：理解概念 → 走方法知识地图的"指标"章节，教学式讲解。

**例 2**：用户："我想在 LEVIR-CD 上做建筑变化检测，标注很少，用什么方法？"
```json
{"domain":"change_detection","task":"建筑变化检测","scenario":"building","modality":"optical","supervision":"semi_supervised","input":"bitemporal","output":"binary_change_map","difficulty":"unspecified","metric":"unspecified","goal":"choose_method"}
```
→ 路由：选方法 → 走方法知识地图的"半监督"分支 + NORA 的 lit-review。

**例 3**：用户："我的模型小目标漏检严重，F1 一直上不去，怎么改？"
```json
{"domain":"change_detection","task":"改进模型","scenario":"unspecified","modality":"unspecified","supervision":"unspecified","input":"unspecified","output":"unspecified","difficulty":"small_object","metric":"f1","goal":"improve_method"}
```
→ 路由：改进方法 → 走"小目标漏检"的实验陷阱 + 方法知识地图的多尺度方案。

## 五、这个理解器在整个导师流程里的位置

```
用户问题
  → ① 遥感问题理解器（本文档）：模糊问题 → 九元组
  → ② 路由：根据 goal + domain，决定走哪条路
        ├─ understand_concept → 方法知识地图 + 教学式讲解
        ├─ choose_method     → NORA lit-review + 方法知识地图
        ├─ improve_method    → 实验陷阱诊断 + ResearchAgent 思路迭代
        ├─ literature_review → NORA lit-review + PaperQA2 证据
        └─ write_paper       → NORA 论文工作流
  → ③ 教学式对话（记忆 + 递进 + 确认理解）
```

---

*诚实边界：九元组和枚举值是第一版设计，需在真实对话里迭代；不声称已经完备。*
